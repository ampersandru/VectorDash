# VectorDash 0.3.46-beta.2

Includes the video OCR, evidence-aware retrieval, RTF extraction and benchmark improvements from beta.1, plus these automatic-indexing fixes:

- Ambiguous journal basename lookups no longer recursively scan matching live directories. Directory metadata is refreshed on its own; unchanged file candidates are skipped.
- Adding exclusions preserves valid journal replay. Removing an exclusion requests catch-up only for overlapping sources rather than unrelated drives.
- Monitoring is configured before restarted scans, preventing startup recovery work from being queued behind a scan already covering it. Interrupted change-monitor runs resume queued affected paths instead of restarting all sources.
- Added **Periodic network-drive catch-up scans** and an editable interval in Scheduling. Enabled by default at **5 minutes**. Folder notifications remain active when disabled; startup and genuine missed-event recovery can still run.
- Periodic network catch-up waits for active indexing and restarts its timer after successful coverage, reducing back-to-back catch-up runs.
- Quiet journal progress is checkpointed after all ambiguous names have been checked and no durable indexing work remains, avoiding replaying already-checked noise after restart.
- Automatic-run deadlines are published before enabling concurrent checks. Run history now shows the actual stop/failure reason.
- Registered missing/new UI messages in localization catalogs.

## What to test

In Scheduling, choose whether periodic network catch-up is enabled and set the interval. Save once; changing only the catch-up interval should not trigger a source restart.

Create one file, edit one existing file, and create a subfolder with a file on a local indexed NTFS drive. Normal journal updates should stay targeted. Create and rename a directory containing files to confirm genuine subtree changes are still discovered. Add a browser exclusion on C: and confirm unrelated drives are not rescanned. Test T: changes with periodic catch-up both enabled and disabled.

A genuine journal gap, missed-event recovery, expanded source coverage or explicit manual update can still require a broader scan. Existing queued work from earlier versions may need to drain once. This beta keeps completed index data and does not rebuild embeddings merely because an unrelated exclusion changes.
