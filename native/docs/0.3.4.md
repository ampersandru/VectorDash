# Native preview 0.3.4

- Model unloading has an independent background timer and an explicit log entry. Active requests are protected; remote servers are never stopped. OCR/media helpers remain on demand.
- Buttons and selection controls have visible thin borders. Native corner rounding no longer competes with the custom rounded client region.
- Sources and exclusions use matching fixed-height scrollable lists, multiple selection, Select/Deselect all, and Remove selected. Common `*.tmp`, `*.log`, `*.bak`, `*.temp` presets are available. Wildcards also work when entered in the manual exclusion list.
- Optional recursive folder-change monitoring queues additions, modifications, renames and deletions, then performs targeted updates under CPU/GPU/input/AC idle rules. A ten-second debounce combines bursts; bounded queues recover with a scan if notifications overflow. Windows uses ReadDirectoryChangesW through the native notify backend. This does not replay the USN journal: changes while the app was closed still need a scheduled or manual scan. No administrator access is required.
- A scoped search reports when its folder/drive has not been indexed.
- The user-supplied logo has a transparent outer background and is embedded in the Windows EXE, installer, tray and main-window header.
- Settings includes Check for updates, download/install, startup checks and optional automatic installation after indexing/setup finishes. The Rust channel selects compatible native Windows assets, verifies GitHub SHA-256 and size, then verifies again before execution. Portable builds link to release downloads instead. Setup remains unsigned. Updating closes VectorDash and its owned model server, then starts the updated app.

The log review found a completed 1,122,481-file scan with eleven changed files; access-denied system folders and a failing T: network path accounted for warnings. Windows network error 59 now stops that source early while retaining its indexed records. The review did not find a currently running llama-server process.

Windows mechanisms: [directory notifications](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) track recursive changes while running; the [NTFS USN journal](https://learn.microsoft.com/en-us/windows/desktop/FileIO/change-journals) can recover changes between sessions but requires persistent journal/path tracking and may need volume access privileges. Journal replay is not implemented in this preview.

Validation: 49 native regression tests passed, including actual recursive Windows notifications, targeted subtree deletion without disturbing sibling files, idle gating with manual scheduling, owned-process idle unloading and tampered-installer rejection. An explicit live test downloaded the published 95,908,237-byte GitHub installer and verified its SHA-256. Desktop compositor edges remain subject to visual confirmation on the target PC.

Explicit picture/photo/image and video/clip queries prefer the requested media type over document text or other media; image previews omit raw OCR excerpts. A live test on the installed app confirmed automatic server exit about 61 seconds after the last embedding request with a one-minute unload setting, without pressing Stop.

A controlled backend fixture with a higher-scoring PDF, a photo and two videos returned only the photo for `picture of dogs`, and the two videos for `video of dogs`. The fixture uses a mock query vector to isolate ranking/filter behavior; these are not new model accuracy benchmarks.
