# VectorDash 0.3.46-beta.4

- Automatic updates now allow a fresh 10-second batching window after completion, preventing queued changes from immediately launching another job using an expired timer. Continuous changes retain the maximum-latency rule.
- Network directory creation/rename discovery uses bounded metadata reconciliation and queues individual differences instead of launching a recursive indexing job for that directory. Removed paths retain deletion checks.
- Unavailable child watch locations (for example T:\hermes) are skipped when a healthy ancestor watch can detect their return. Parent notifications or monitoring reconfiguration can reattach them; disconnected share roots retain reconnect retries. Existing index entries are not deleted just because a path is inaccessible.
- A failed branch now restarts only its closest watch, leaving a healthy parent watch running.

Periodic network catch-up can remain disabled while testing normal SMB notifications. Metadata recovery still runs for genuine coverage gaps. Local directory creation/rename can still require discovering that subtree; this update does not eliminate all metadata enumeration.

Validation: full suite 470 passed before the final closest-watch adjustment; all 33 monitoring tests passed after it, plus two controlled live T: tests (exactly four paths for one new file and three edits; nested/new branch notification delivery).
