# VectorDash 0.3.45-beta.2

## Clipboard performance

- Stop checking an empty OCR/image-embedding queue every two seconds. New image captures, imports and relevant settings changes invalidate the empty result; a once-per-minute safety check handles changes from outside the app. Existing captures still use the normal two-second worker cadence.
- Add indexes for embedding candidates, pending OCR and retention. Candidate checks read index metadata instead of repeatedly traversing large encrypted clipboard payloads.
- Perform schema inspection/index migration once, using the database schema version for subsequent connections. Existing history, saved items and encrypted payloads are retained.
- Respect capture pause for background image embedding as well as OCR.

## Includes beta.1 fixes

Mapped network monitoring/scanning resolves the UNC share while retaining configured drive-letter identities, with a five-minute network catch-up. Quick-search dismissal works after speech ends/stops and keeps the popup open during AI generation and active/paused speech.

## Validation

Migration, query bytecode, candidate selection, empty-queue timing and actual image-capture wakeup regressions are included. On a disposable copy of the reported database, the indexed lookup reduced SQLite page-cache misses from 7,985 to 7 and median lookup time from 15.485 ms to 0.0335 ms (APSW benchmark, four fresh connections per case). These are query measurements, not physical disk or whole-app CPU measurements. The source database was opened read-only; the disposable copy was deleted after testing.

After installation, fully restart VectorDash and repeat a 10–30 second idle Procmon recording. The regular two-second bursts of thousands of clipboard.sqlite reads should disappear. Some activity remains for retention cleanup, user actions, new captures and the one-minute safety check. Copy a new image to confirm capture and subsequent image search still work.
