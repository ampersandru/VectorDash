# VectorDash 0.3.46-beta.1

- Sampled video frames now use the configured optional OCR engine and languages. Text matches retain the frame timestamp, separately from visual and audio embeddings.
- Corrected FFmpeg sampling alignment so a sampled frame is not labelled with a timestamp before its scene begins.
- Search explains whether evidence comes from video frames, frame text, or audio. CLI/MCP results include structured supporting evidence.
- Explicit combined visual/audio and ordered video queries use bounded multi-part reranking (up to three parts). Results remain semantic candidates, not guaranteed scene understanding.
- Content ranking normalizes surrounding punctuation consistently, so constraints such as “Site 000:” can match “Site 000”.
- RTF documents index readable text rather than formatting markup, including Unicode and escaped characters.
- Added a larger deterministic synthetic corpus generator and scoring for file hits, supporting modality, exact identifiers, and timestamp/order correctness.

## Testing

Enable OCR and its required language packs, then run Update on Full-indexed video and RTF folders. Changed extraction fingerprints refresh affected content without rebuilding unrelated files. OCR increases video indexing time; it follows the existing video sample interval and similar-frame setting, so short scenes or tiny text can still be missed.

Try an on-screen identifier, a visual/audio query using “while”, and a video query using “then”. Compare the selected timestamp with the actual content. Existing index files remain local. See docs/RETRIEVAL-BENCHMARK.md for reproducible evaluation.

Thanks to the author of issue #23 for the reproducible multimodal benchmark that motivated these changes. No new model accuracy or speed claims are made from the synthetic tests.
