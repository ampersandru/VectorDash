# Native preview 0.3.3

## Indexing

Idle thresholds now measure other applications. Windows job accounting subtracts VectorDash, its owned llama-server and parsing helpers, including helpers that finish between samples. GPU engine counters exclude owned process IDs. CPU/GPU limits still pause automatic indexing when other applications are busy; manual Pause/Cancel remain available.

Sources shows whether an update is checking filenames, reusing content, extracting content, or embedding with EmbeddingGemma 2 on the local CPU/GPU or a remote server. A per-file content-chunk counter updates between batches. Logs explain why content needs processing.

Unchanged text documents do not re-embed just because OCR, image/audio/video or projector settings change. Older Full content can be reused when its completed file metadata verifies an unchanged file, even if the names table has an unknown size. Relevant model, file or extraction changes still refresh content.

HTML reads visible text rather than scripts/styles/templates and markup. Existing HTML content refreshes once to apply this change. Unsupported types get filename entries without launching a parser or scanning content tables. Size/date-only updates preserve filename keyword entries rather than rebuilding them. Sources counts actual vector-backed files separately from filename-only entries. Models can unload during a names-only scan; active embedding requests remain protected.

Local checks: the reported 2.4 MB HTML benchmark shrank from 1,498 chunks to one, extracted in about 0.18 seconds. The reported CSV still contains 1,490 chunks, extracted in about 0.42 seconds; embedding that much content takes additional model time. In a synthetic 502-file fixture, the initial scan took about 0.47 seconds with two mock embedding requests, and unchanged scans took about 0.20 seconds with zero requests. Unrelated-setting changes and verified legacy metadata also made zero embedding requests. These are targeted checks, not general end-to-end GPU benchmarks.

## Search and appearance

- Up/down selection scrolls into view, including virtualized off-screen results.
- Result text is not separately selectable, so double-clicking any row text opens the file.
- Ctrl+C handles Windows copy events and supplies a valid clipboard owner plus a Unicode file-drop payload. Selected query text and other text fields retain normal text copying.
- Native borders are disabled and the rounded window region matches the painted client area, removing the oversized corner outline.
- File-type exclusions accept `log`, `.log`, `*.log` and lists such as `*.log, *.tmp`; `*.log.*` and `*.tar.gz` also work. Sources exclusions affect indexing and search; search exclusions affect the current results.
- **Settings → Explorer double Ctrl: search current folder/drive and subfolders** is enabled by default. Explorer activation uses its active filesystem view as the search scope. Change the scope dropdown to All sources whenever needed. Non-filesystem views fall back to All sources; folders must already be indexed. Open/Save dialog and ordinary global-shortcut behavior are unchanged.

Exit VectorDash before installing. No database conversion or model reinstall is required. The setup is unsigned and this remains a preview.
