# VectorDash 0.3.25 Beta 2 — Indexing controls and Windows 10 beta

This is a test build on PR #16. Windows 10 support is **beta**, targeting Windows 10 version 2004/build 19041 or newer, x64. The installer no longer requires Windows 11. Actual Windows 10 device validation is still needed; compatibility branches were exercised on Windows 11. Windows 10 uses a rounded tinted fallback rather than the Windows 11 host-backdrop effect.

- Prepare one bounded batch ahead while the current batch embeds. Common Rust-decoded images avoid per-image process startup; other image/OCR parsers retain process isolation.
- Long documents yield in slices starting at 32 new chunks so other files can progress. Non-PDF slices grow on later turns to limit repeated parsing. Saved slices stay staged until the complete file can replace its old searchable content atomically; PDF resumes at its saved page. Other document formats may re-extract earlier content while reusing saved embeddings. Audio/video retain one streaming pass to avoid repeatedly decoding earlier media.
- Choose **Quick first** or **Full first** in Sources. Deferred work is durable and resumes under current source/idle rules without a second drive crawl.
- Optionally skip near-identical sampled video frames, preserving scene changes and timestamps. This saves embedding requests; candidate frames still need decoding. An ordinary Update index refreshes affected Full-indexed videos after changing this setting.
- Browse **Images** and **Videos** in a thumbnail grid, with keyboard navigation, context actions and a resizable preview. Disable the grid in Settings if you prefer the list.
- Learned timing estimates cover known queued Full work after enough completed samples. They are approximate, backend-specific and exclude undiscovered files.
- Choose **FP32** (default) or **FP16** semantic cache precision in Settings. FP16 halves vector storage in RAM, with FP32 scoring; the on-disk index stays FP32. No index update is required. Low memory mode continues streaming FP32 from disk.
- Optional **Rank Calibration** in Sources adjusts cross-media semantic ranking at search time. It does not change the embedding model's output or stored vectors. **No index update is required**, including for already Full-indexed items.
- Search loading and EmbeddingGemma waits show a blue circulating outline. Search, dictation and AI notices share a centered footer and expire after completion or a few seconds. AI responses show elapsed request time; read-aloud Pause/Play/Stop controls stay in that footer.
- Search/Clipboard previews use the available vertical space and preserve media aspect ratios.

Measured results and limits: [BENCHMARKS.md](BENCHMARKS.md). FP16 is a memory option, not a guaranteed speed improvement. This generated test corpus does not establish broad relevance quality.
